## Accessibility

<h2 id="isPasted">Use cases</h2>

<p>People should be able to do the following using assistive technology:</p><ul><li>Navigate to each button and interact with them</li><li>Navigate to any element opened by the trailing button</li><li>Understand the current selection state of the button</li></ul>

<h2 id="isPasted">Interaction &amp; style</h2>

<p>Each button in the split button needs a minimum target area of 48x48dp. Extra small and small split buttons are shorter than 48dp, so the target areas around them need to be at least 48dp tall.</p>

<h2 id="isPasted">Labeling elements</h2>

<p>The accessibility label for the leading button is the same as buttons.</p>

“Watch later” is both the button label text and the accessibility label.

<p><span style="white-space:pre-wrap">Leading buttons should have the same labels as common buttons</span></p>

imageUrl: https://firebasestorage.googleapis.com/v0/b/design-spec/o/projects%2Fgoogle-material-3%2Fimages%2Fm0dq2sfs-3.png?alt=media

<p>The trailing icon button should have an extra state or similar label indicating that the menu is expanded or collapsed.<br /><br />Label the button to clearly indicate that there are more options. The label of the secondary button should indicate that it provides additional choices related to the action of the main button. For instance, if the main button says "Watch later," the secondary button should be something like "More watch options."<br /><br />Label the opened menu according to the <a href="/m3/pages/menus/accessibility/" target="_blank" rel="noopener noreferrer">menu accessibility guidance</a>.</p>

Collapsed state indicated for the trailing button.

<p><span style="white-space:pre-wrap">Trailing buttons should communicate the state of the menu and that more options are available</span></p>
